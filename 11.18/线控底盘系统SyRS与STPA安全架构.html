面向高阶智能驾驶的线控底盘系统需求规格书与安全架构

01 · Introduction

概述

系统需求只描述抽象功能与可度量的约束，不规定具体实现；实现方案在初始架构与安全架构中进一步展开。

SyRS 1.1–1.4
1.1

系统目的

线控底盘通过电信号替代机械、液压或机械液压混合式硬连接，接收自动驾驶系统输出的运动控制指令，完成转向、制动和驱动的闭环执行，为高阶智能驾驶提供安全、实时、可冗余控制的车辆运动执行能力。

1.2

系统范围

本系统范围覆盖自动驾驶域接口、底盘域控制、线控转向、线控制动、线控驱动、关键传感器反馈、通信与电源保障。系统不替代自动驾驶系统的环境感知、行为决策和轨迹规划。

包含 ADC 控制指令接收、运动协调、SBW/BBW/DBW 执行控制、车辆状态反馈、故障诊断与安全降级。
不包含 摄像头、激光雷达、毫米波雷达的目标识别与融合，以及高精地图和全局路径规划。
1.3

系统概况

1.3.1

系统环境

系统运行于城市道路、高速道路、乡村道路、拥堵路段及雨雪雾等环境；运行设计域 ODD 需由整车级自动驾驶系统定义，底盘系统据此提供车辆运动执行能力。

1.3.2

系统功能

核心功能包括目标运动指令接收与校验、车辆纵向/横向运动控制、转向制动驱动协调控制、执行状态监测、故障检测隔离与安全降级。

1.3.3

用户特征

自动驾驶系统发送目标运动指令，接收车辆状态与故障反馈。
驾驶员 / 乘客在 L3 接管请求或人工驾驶模式下参与控制与监督。
维修 / 运营人员通过诊断、OTA 和远程运营接口完成维护、升级与监控。
1.4

定义

本报告中的缩写与术语见附录 5.2。关键概念为：线控转向 SBW、线控制动 BBW、线控驱动 DBW、底盘域控制器 CDC、系统理论过程分析 STPA、最小风险状态 MRC。

03 · System Requirements

系统需求

需求分为功能、可用性、性能、接口、运行、模式与状态、物理、环境、安保、信息管理、政策法规、生命周期支持及包装运输，共 13 类，与表 5-1 对应。

SyRS 3.1–3.13
3.1

功能需求

线控底盘应接收并执行运动控制指令，实现纵向、横向和横摆运动控制，并具备故障检测、隔离和降级能力。

编号需求描述归属
FR-01接收 ADS 目标车速、目标加速度和目标转向角等指令。系统级
FR-02根据目标运动状态实现纵向速度闭环控制。CDC/BBW/DBW
FR-03根据目标轨迹实现横向转向控制。CDC/SBW
FR-04实现驱动、制动和转向的协调控制。CDC
FR-05支持车辆横摆稳定性控制。CDC
FR-06支持紧急制动、紧急避障等紧急运动控制。CDC/BBW/SBW
FR-07按目标转向角控制前轮转角，并反馈转向状态。SBW
FR-08具备转向角、转向力矩和转向执行故障监测。SBW
FR-09在主转向通道故障时切换备用通道或进入降级状态。SBW
FR-10按目标减速度生成制动力，并支持摩擦制动与回馈制动协调。BBW/DBW
FR-11具备主制动通道故障后的备用制动能力。BBW
FR-12支持紧急制动和失效降级制动。BBW
FR-13按目标驱动转矩控制驱动电机，并检测非预期转矩。DBW
FR-14监测关键传感器、通信、电源和执行器状态。CDC
FR-15识别异常、冲突或过期指令，并执行安全降级。CDC
3.2

可用性需求

可操作性自动驾驶与人工接管模式切换应连续、无突变，控制权状态清晰。
可维护性支持故障码、冻结帧、执行器测试、标定和 OTA 升级。
3.3

性能需求

性能指标用于概念阶段初步论证，实际值需结合目标车型、执行器选型和控制回路进一步确认。

性能指标建议目标说明
底盘控制周期5–10 ms由控制回路实时性确定
控制指令延迟≤20 ms 目标值从接收到执行响应的延迟
转向角跟踪误差≤0.5° 目标值需明确工况与统计方法
纵向加速度跟踪误差≤0.1 g 目标值需明确测量条件和评价窗口
故障检测与切换满足安全目标时间预算不能仅用固定切换时间评价
说明：初步答案中“MTBF≥10000 h”“故障覆盖率≥99%”等数值可作为目标，但必须明确验证样本、置信水平和运行条件，避免把未经验证的指标直接写成结论。
3.4

接口需求

3.4.1

外部接口

自动驾驶域接口：接收目标运动状态与运行模式，上传底盘状态、故障和最小风险状态请求。整车域接口：接收整车模式与能量管理信息，反馈底盘工作状态。人机接口：输出故障告警和接管请求。

3.4.2

内部接口

CDC 与 SBW/BBW/DBW 之间传输控制指令和执行状态；执行器与传感器之间传输转向角、轮速、制动压力、电机转矩等反馈信号；安全监控通道应尽可能采用独立数据路径。

接口传输内容主要要求
ADC ↔ CDC目标转向角、目标车速、目标加速度、模式、状态反馈高带宽、低时延、完整性、时效性
CDC ↔ SBW/BBW/DBW子系统控制指令与执行状态确定性、实时性、故障检测
传感器 ↔ CDC转角、轮速、压力、横摆率、加速度、电流、温度时间戳、有效性、冗余或交叉校验
整车 ↔ 底盘整车模式、能量状态、底盘故障与健康状态状态一致、可追溯
3.5

系统运行

系统运行分为上电自检、待机、正常运动控制、故障降级、最小风险机动、安全停车、维护与 OTA。L3 故障时可请求驾驶员接管，L4 不能把驾驶员接管作为唯一安全机制。

3.6

系统模式与状态

模式状态说明控制权
自动驾驶模式ADS 发送运动指令，底盘闭环执行。ADS
人工驾驶模式驾驶员通过踏板、方向盘输入，底盘辅助执行。驾驶员
故障降级模式限制速度、加速度或横向机动。底盘安全策略
最小风险状态减速、靠边、安全停车并驻车。底盘安全策略
维护 / OTA 模式诊断、标定、软件升级和回滚。授权维护
3.7

物理特征

底盘执行器应满足安装空间、质量、功率、热管理和振动耐久约束；转向执行器、制动执行器和驱动电机应满足整车总布置及碰撞安全边界。

3.8

环境条件

系统应适应车载温度、湿度、盐雾、振动、电磁兼容和低附着路面等环境。关键电子部件需满足车规级温度与寿命要求，底盘控制算法应能随路面摩擦系数和车辆姿态变化自适应调整。

3.9

安保需求

安全相关控制指令应具备来源可信、完整有效、时效性和合理性校验；诊断、OTA、远程运营接口应具备身份认证、授权、审计、防重放和数据完整性保护。

3.10

信息管理需求

应记录关键事件、故障冻结帧、控制指令与执行状态，用于事故分析、法规审计和车队管理。数据应具备时间戳、版本、权限和防篡改能力，同时符合隐私与数据保护要求。

3.11

政策与法规需求

应满足适用道路交通安全法规、自动驾驶准入、功能安全、预期功能安全、网络安全和数据合规要求。L3/L4 最小风险机动能力应与目标运行设计域和法规要求保持一致。

3.12

系统生存周期支持需求

应支持全生命周期内的诊断、预测性维护、软件升级、备件管理和安全事件分析；关键安全证据应可追溯至需求、设计、测试和运行数据。

3.13

包装、处理、装载、运输需求

总成和关键电子器件应满足运输与仓储的防潮、防静电、防振动和标识要求；高压电池、功率器件和含稀土电机的处置需符合环保法规。

06 · Initial Architecture

初始系统架构

采用“自动驾驶域控制器 + 底盘域控制器 + 分布式线控执行器”的分层架构。底盘域控制器负责运动协调、指令分配和故障管理，线控执行器负责具体执行。

ADC + CDC + SBW + BBW + DBW
决策层自动驾驶域控制器 ADC
环境感知、行为决策、轨迹规划、目标运动状态
协调控制层底盘域控制器 CDC
运动控制、轨迹跟踪、转矩 / 制动力分配、故障管理
执行控制层SBW / BBW / DBW 控制器
转向、制动、驱动闭环控制
状态反馈层转角、轮速、压力、电流、姿态传感器
采集车辆与执行器状态
6.1

功能架构

子系统主要功能核心控制对象
线控转向 SBW控制车辆转向角及转向力矩转向执行电机
线控制动 BBW制动力分配与车辆减速制动执行器
线控驱动 DBW驱动力与驱动转矩控制驱动电机
底盘域控制 CDC运动控制协调、指令分配、故障管理各底盘执行系统
6.2

CDC 软件功能模块

指令接收与校验接收 ADS 指令，检查合法性、时效性与合理性。
运动控制与分配计算目标横摆、纵向和横向控制量，分配转向、制动和驱动指令。
安全监控与故障管理检测异常、诊断、隔离并触发降级控制。
6.3

通信架构

自动驾驶域与底盘域之间采用高带宽车载以太网；底盘域与执行控制器之间采用 CAN FD 或车载以太网；关键安全控制通道应设置独立通信路径或冗余能力，并监控超时、丢帧、计数器和数据有效性。

07 · Control Structure

系统控制框图

控制框图对应 STPA 的分层控制结构，仅表达控制器、执行器、受控过程和传感器之间的功能交互，不包含具体硬件实现。

Control Loop

蓝色箭头为控制指令流，绿色箭头为执行器作用于受控过程，黄色虚线为传感器与状态反馈。反馈同时回到 CDC 和 ADC，形成底盘运动闭环与自动驾驶状态闭环。

7.1

控制框图节点与接口细节

节点 内部模块 关键输入 关键输出 细节说明
ADC 环境感知、行为决策、轨迹规划、目标运动状态生成 目标、车道、障碍物、地图、定位、车辆状态 目标转向角、目标车速、目标加速度、模式请求 不直接控制底盘执行器，只输出运动意图；需向底盘提供故障和最小风险状态请求。
CDC 指令校验、状态估计、运动控制、控制分配、安全监控、故障管理、通信电源监控 ADC 指令、车辆状态、执行器反馈、通信与电源状态 转向、制动、驱动指令，故障降级策略，安全干预 是运动协调与安全仲裁的核心；需检查指令合法性、合理性、时效性，并在子系统冲突时进行仲裁。
SBW 主备转向控制器、执行电机、路感模拟、转角传感器、电源通信监控 CDC 转向指令、方向盘转角、车速、驾驶模式 实际前轮转角、转向执行状态、故障状态 主备通道需避免共因失效；执行电机和转角反馈是转向闭环与安全监测的关键。
BBW 主备制动控制器、制动执行器、轮速与压力传感器、独立备用制动路径 CDC 制动指令、轮速、制动压力、车辆状态 实际制动力、制动执行状态、备用制动状态 制动是进入最小风险状态的重要基础，需保证制动力建立速度、分配合理和备用能力独立。

传感器 转向、制动、驱动、整车状态四类传感器 方向盘转角、车轮转角、轮速、压力、加速度、横摆率、转矩、温度 双通道或可信状态信号、故障状态 关键状态应具备时间戳、有效性、冗余或交叉校验能力，异常数据不得被无条件采信。
08 · STPA

系统理论过程分析

STPA 从控制关系出发识别损失、危险、安全约束、不安全控制行为和致因场景，弥补 FTA/FMEA 仅关注部件失效的不足。

Loss → Hazard → SC → UCA
8.1

系统损失与系统级危险

编号系统损失 / 危险说明
L1人员生命安全损失车辆失控导致驾驶员、乘员或其他道路参与者伤亡。
L2车辆重大损坏严重碰撞或失控事故。
L3交通安全损失车辆异常运动引发连锁交通事故。
H1非预期转向错误方向的转向动作或转向角过大。
H2转向能力丧失车辆无法按安全要求控制行驶方向。
H3非预期驱动驱动系统输出非预期驱动转矩。
H4制动能力丧失车辆无法按安全要求减速或停车。
H5非预期制动在不适当时机产生过大制动力。
H6底盘协同控制失效转向、制动和驱动指令不协调导致失稳。
8.2

系统安全约束

  • SC1

    转向指令不得超过车辆动力学允许范围。

  • SC2

    转向控制必须具备执行状态反馈和异常监测能力。

  • SC3

    驱动系统不得产生非预期的驱动转矩。

  • SC4

    制动系统必须具备满足安全目标的备用制动能力。

  • SC5

    制动与驱动不得产生危险的冲突控制行为。

  • SC6

    底盘控制器必须识别无效、超时和异常控制指令。

  • SC7

    关键传感器异常时不得继续无条件使用错误数据。

  • SC8

    关键通信故障时必须采取预定义的安全控制策略。

  • SC9

    单一故障不得直接导致不可接受的车辆失控风险。

  • SC10

    无法保证正常控制时，应进入可控降级或最小风险状态。

10 · Safety Architecture

安全架构

安全架构把控制器冗余、执行器冗余、独立安全监控、通信与电源冗余、分级降级控制落实到具体层级。

Fault Detection + Redundancy + MRC
10.1

安全架构总体设计

架构层级核心组成安全设计目标
自动驾驶控制层ADC、备用运动控制能力避免错误运动指令传递
底盘主控制层主 CDC完成正常运动控制
独立安全监控层安全监控控制器监测主控制器异常
执行冗余层SBW / BBW / DBW 备用通道保障关键执行能力
电源与通信保障层双路供电、冗余通信网络避免公共资源失效导致失控
10.2

主备控制器与独立安全监控

主底盘控制器负责接收 ADS 指令、计算目标运动状态并分配控制指令；安全监控控制器独立监测主控制器运行状态、指令有效性、车辆状态偏差、通信和电源异常，并在必要时触发安全降级。安全监控不应完全依赖主控制器自报状态。

10.3

转向、制动、驱动安全冗余

SBW 安全设计主备控制通道、转角交叉校验、执行机构监控、故障隔离、限速与安全停车。
BBW 安全设计备用制动通道、独立或冗余状态监测、备用能源、制动与驱动协调。
DBW 安全设计转矩合理性监测、输出限幅、实际转矩反馈、逆变器监测、独立转矩抑制。
10.4

通信与电源安全冗余

关键控制信号采用冗余通信路径，并配置 CRC、计数器、时间戳和超时监控；主电源和关键执行器电源应独立供电、隔离故障。冗余网络应避免共用电源、连接器和布线路径，以降低共因失效。

10.5

故障分级与最小风险状态

故障等级故障状态系统响应
F0无故障正常自动驾驶
F1非关键故障报警并维持功能或受限运行
F2单一关键通道故障，备用可用切换备用通道，限制车辆性能
F3多个关键功能受限退出正常控制，启动最小风险机动
F4关键执行能力严重丧失执行可用紧急安全策略，避免进一步危险
最小风险状态目标：保持必要方向稳定性，限制非预期驱动转矩，保留可用制动能力，按环境与车辆状态控制减速度，尽可能安全靠边停车，并在停车后维持驻车制动。L3 可请求驾驶员接管；L4 应能由系统自主完成最小风险机动。

最终结论：高阶智能驾驶线控底盘应采用分层、分布式、冗余化架构，以底盘域控制器为运动控制核心，以 SBW/BBW/DBW 为执行基础；通过 STPA 形成系统安全需求，再以控制器冗余、执行器冗余、通信电源冗余、独立安全监控和分级降级构成安全架构，形成从需求到验证的完整闭环。
